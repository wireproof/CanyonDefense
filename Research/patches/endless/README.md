# Free Play test candidate

The original game reaches a victory dialog at the end of a finite wave program and its OK button exits to scoring. The candidate adds a Free Play button to the victory dialog while retaining OK, resumes the same map and tower objects, then creates further waves using the last ten waves as templates with increasing levels capped at 50. The original loss and scoring path remains. It also avoids indexing past the finite wave list while the last wave is still active. The current game's drag fix remains in the separate Web wrapper.

`test.cjs` checks real extracted method bodies for wave boundary behavior and the transition, including 10,000 additional waves. FFDec successfully compiled and re-exported the candidate. An instrumented test-only SWF, built from the candidate with automatic victory and a scripted call to the new button handler, ran in isolated headless Ruffle 0.7.1. It emitted CANYON_TEST_BUTTON_READY, CANYON_TEST_CONTINUE_OK, and CANYON_TEST_WAVE_OK. A second isolated test visually displayed the Free Play and OK buttons on the victory dialog. The debug instrumentation is not in the candidate SWF. These tests do not establish actual touch operation, real completed-game tower preservation, balance, phone/iPad performance, or orientation behavior on physical hardware.
